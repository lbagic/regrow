# Changelog

## Unreleased

- Engine protocol (PR 3 of the personal-first plan): `regrow engine` speaks JSON lines over stdin and stdout so a shell app can watch free space, scan, plan and execute without a terminal; [docs/ENGINE.md](docs/ENGINE.md) is the contract. `hello` reports the protocol version and whether the process has Full Disk Access. Scans open with a free-space sample and stream one `finding` per rule as it completes, with its scan time, then a `summary` with the four buckets and each item's exclusive bytes; `plan` takes the scan's id and an optional selection (absent: the default selection; empty: nothing) and returns a single-use plan id that expires after 10 minutes of wall-clock time (sleep counts) and dies when a newer scan or any execute of the same scan starts; `execute` streams each oplog line after it is on disk; `cancel` stops a scan at once and an execute after its current action. One scan or execute runs at a time. Actions that need sudo are skipped with the Terminal command to run instead. Steward commands and the docker volume export run with an empty stdin and captured output, and a failure journals the output's tail. A Trash move that hangs on a blocked folder fails after 60 s instead of holding the run. `tick` runs one pass of the watch loop (sample, forecast, alerts, and with `autotrim` the gated Go build cache prune), as `regrow tick` does. A plan whose selectors address nothing is refused, as `regrow clean` refuses. When stdin closes, a scan is canceled, and an execute finishes its current action and a tick its pass before the engine exits. `regrow scan --json` now prints the same scan events, one JSON object per line, instead of a `{findings, totals, exclusive}` object, and exits 1 when its output cannot be written. The default selection (TUI pre-ticks, `plan` and `clean` without ids) no longer includes items nothing could be measured of.
- Agent session scratch (PR 6.1 of the personal-first plan), behind `--beta-rules`: Claude Code's per-session scratch under `/private/tmp/claude-<uid>/` is listed per session. Sessions that ended (no running process belongs to them or works inside their scratch, and no change to the transcript or the scratch for 24 h) are offered to the Trash under "Agent session scratch (ended sessions)", caution, never pre-selected; `regrow clean agent-scratch/<path>` names one, by the path the scan lists. Every other session shows under "Agent session scratch (kept)" with why: running, a running process works inside it, recently active, not fully readable, or holding a git worktree (either a worktree of a repository elsewhere or a repository with a worktree elsewhere, which must be removed first). If regrow cannot tell which sessions are running (a `claude` process in no session registry, a registry it cannot read), both rules say so and offer nothing. Each session is checked again right before its Trash move, and the move is refused if the session came back to life after the scan; for that, `pre_action` hooks now also gate Trash moves. A new catalog test keeps one owner per byte: no two rules may name the same path (also in another case or through `/tmp`) or discover the same directory name.

- Prune hardening: `regrow prune go-build --yes` no longer reports a failure when Go trims its cache or `go clean -cache` runs at the same time, and it refuses a Go build cache that is not on the disk whose free space regrow watches. `regrow tick --autotrim` still prunes when its history file cannot be read, judging by the 50 GiB line alone, and an unreadable oplog fails only the ticks that would prune.

- Headroom and prune (PR 4 of the personal-first plan): `regrow tick` takes one sample of free space (what df shows), APFS purgeable space and swap, appends it to `~/.local/state/regrow/headroom.jsonl` (30 days), forecasts days-to-full from the trend since the last clean, and prints the alerts that crossed: free space below 50/25/10/5 GiB, days-to-full under 3, swap up 4 GiB or free space down 5 GiB within 30 minutes (these two name the process holding the most memory). Each alert fires once per crossing, not on every tick. `regrow prune go-build` shows how much of the Go build cache it would delete: entries unused for 48 hours, oldest first, until about 15 GiB is left; `--yes` deletes them directly (no Trash, no undo; the next build recompiles what it needs), refuses while a `go`, `compile` or `link` process runs (other than the `go run` that started it), deletes only entries in Go's shard directories, and journals what it deleted. `regrow tick --autotrim` runs the same prune when headroom is low (under 50 GiB free, or under 3 days to full), defers while a build runs (after 2 hours with under 10 GiB free it prunes anyway), and is refused until one manual `regrow prune go-build --yes` has completed. The policy lives in the rule's new `prune:` block. Plan lines now quote arguments that hold glob characters, so a printed command can be pasted. A journal line cut short by a full disk no longer stops `regrow undo` and `regrow history` from reading the oplog.

- Scan correctness (PR 2 of the personal-first plan): a scan no longer hangs on a folder macOS never answers for (another app's container without Full Disk Access). Every filesystem call is bounded; a folder that stays silent while nothing else in the scan answers is written off after 5 s and left alone until it answers, and the item is reported as a lower bound. Tool queries (docker, simctl, tmutil) give up after 2 minutes and say so on the rule, so a wedged Docker VM no longer stalls the scan. Sizes that are lower bounds read "≥ X", targets that could not be read at all read "unreadable" (Trash and the Spotlight index used to show `0 B`), each with "blocked or unreadable (Full Disk Access may be needed)"; `--json` items carry `partial: true`. "Last used" is the newest modification time over an item's files and directories instead of the top folder's own. The single "Total found" is gone: totals count every byte once, in the innermost row that holds it, split into frees now / frees after Trash / shown only / macOS-managed, in the scan listing, the TUI footer and `regrow scan --json` (now an object: `findings`, `totals`, `exclusive`). The TUI's selection line reads "selected N · plan ~X · K skipped" and counts a nested selection once. `regrow doctor` reports flagged / normal / unknown; a check it could not fully read is unknown, not healthy, and `--json` carries `verdict` in place of `flagged`. `node_modules` discovery reaches depth 10 (depth 6 missed 32 of 64 on the owner's machine), walks through a symlinked root and reports a directory reached from two roots once. A path under a regular file is treated as absent. Docker build cache counts only records that pruning would free (records shared with an image layer are left out, matching `docker system df`). HuggingFace repos' last-used is now their last download or refresh (newest mtime), no longer blob access time.

- Planner safety (PR 1 of the personal-first plan): Empty Trash now runs before every other action (`empties_trash: true` on `trash-empty`), so a run that also trashes things keeps them restorable with `regrow undo`. Nested selections are planned once: an item inside another selected item is skipped with "inside X, also selected", and the plan total is the union instead of a double-counting sum. An item that holds a surface-only item (or shares its path) is refused. `regrow plan` and `regrow clean` without ids and the TUI start from the same default selection (safe rules that found something); an empty selection plans nothing. Plan output shows what frees space now (steward commands) and what frees it only once the Trash is emptied, with an undo column per action; the blanket "Trash first, undo restores" line is gone. If emptying the Trash fails, the run's Trash moves are skipped with a reason. After a run, the summary separates space freed now, items in the Trash, and items left in regrow staging when Finder was unavailable. `regrow clean` prints skip reasons when everything selected was refused. `regrow help` and `--help` list the subcommands.

- TUI execute-on-confirm: the interactive scan can now run the plan — plan screen (`enter`) → `x` → confirm screen restating the exact actions → `y`. Two explicit gates on two screens; `enter` is inert on the confirm screen so muscle memory can't execute. Confirming quits the alt-screen and executes outside the TUI (native commands keep real terminal stdio — sudo can prompt, docker can stream), reprinting the action list first so the scrollback keeps a record. Same oplog/trash/undo path as `regrow clean`.

- Doctor + phantom space (Prompt H): `regrow doctor [--json]` — a fast, read-only pass over hero-bug scanners and the phantom-space category; it never plans or executes, fix lines point at `regrow clean`. Hero bugs are rule metadata (`doctor: {flag_above, story}`): flagged when the measured total crosses the healthy line, printed with the bug story and the exact fix (steward command spelled out). Shipped scanners: Claude Code debug-log loop (new `claude-code-cache` rule; `~/.claude/projects` never listed), Playwright transform-cache bug (new `playwright-cache` rule), mediaanalysisd leak, Spotlight runaway index. Phantom space is now its own category with why-Finder-lags copy: `tm-snapshots` and `docker-vm-disk` moved in; new `apfs-purgeable` rule measures the Finder-vs-df gap via a JXA Foundation probe (no TCC prompt, no CGo — diskutil/system_profiler cannot see purgeable); `docker-vm-disk` became a tool query labeling real-vs-sparse ("35.5 GiB real of 1.0 TiB sparse"), daemon not required. `HumanBytes` moved to engine (scanner labels format sizes too; tui delegates).

- Docker rules graduated from beta after first real-machine burn-in: the 6 per-item docker rules now show without `--beta-rules`. ML (`ai`) rules stay beta.

- Docker provider (Prompt G2): docker becomes tiered per-item rules instead of aggregate prunes, all `--beta-rules` gated. One snapshot per scan (`system df -v` + trimmed `container`/`volume`/`image inspect`, whatever daemon the current context points at; daemon down = rules don't apply, silently). Volume last-used is *derived* — containers' StartedAt/FinishedAt joined over their mounts — and persisted in a usage ledger (`~/.local/state/regrow/docker-volumes.json`, keyed name@CreatedAt) so history survives `docker rm`/`compose down`. Tiers: in-use/keep-listed/over-cap/recent volumes are surface-only with the reason in the row ("dangling ≠ safe" — the live probe found all dangling volumes were named, active-project DB data); dangling named and stale anonymous volumes are caution, per-item `docker volume rm` preceded by a tarball export to regrow staging (trash-not-rm for data Finder can't reach; 10 GiB cap, undo points at the tarball); stopped-30d+ containers, dangling unreferenced images (by ID — never `image prune --filter until=`, which ages on *build* time) and 30d-unused build cache (`builder prune --filter unused-for=720h`, the daemon's own last-used) are safe. New config file `~/.config/regrow/config.yaml`: docker keep-list (name glob / compose project) and `volume_export_cap`. Engine grew `pre_action` (schema-validated executor hook; export receipts journal like trash receipts, `undo` reports them as manual-recovery). Retired: `docker-prune` and `docker-volumes` (aggregate prunes that couldn't honor the tiers). Verified end-to-end live: export → rm → journal receipt → undo message.

- ML module (Prompt G): 12 new rules under `category: ai`, all `--beta-rules` gated. HuggingFace hub shows per-model/dataset/space rows — enumerated by a cache-layout walker (works when the `hf` CLI is venv-bound or absent; respects `HF_HUB_CACHE`/`HF_HOME`), dedup-aware sizes, last-accessed via atime, deletion trashes the whole repo dir (undoable; equivalent to `hf cache rm` since blobs are per-repo). Ollama shows per-model rows from the manifest store (server may be stopped; respects `OLLAMA_MODELS`) with *exclusive* sizes — what `ollama rm` actually frees — and shared-blob bytes annotated in the label; deletion stays native `ollama rm`. LM Studio models per-dir (both dir generations), GPT4All per-.gguf. Simple cache rules: HF datasets + Xet, torch hub, Whisper, llama.cpp downloads, Keras (config preserved), wandb. ComfyUI/SD-WebUI/Fooocus model libraries found via `models/checkpoints` marker discovery, surface-only — often irreplaceable. Model rules are caution, never auto-selected.

- Item identity (Prompt G0): every scanned item carries a stable id `ruleID/key` (key = tool handle like a sim UDID, else `~`-abbreviated path, else label). `regrow plan`/`clean` accept item ids next to rule ids (`regrow clean sim-devices/AAA-111`); a selector that matches nothing is an error for `clean` and a warning for `plan` — typos never silently no-op. TUI: rules expand (`→`/`l`) into per-item rows with checkbox, size, risk badge and last-used; the rule checkbox shows all/partial/none; footer shows the copy-pasteable item id. Whole-rule commands (`go clean -cache`) keep all-or-nothing selection — the planner refuses partial picks instead of over-deleting. `--json` carries item keys on scan items and `item_key` on plan actions; the oplog journals it. Refits: xcode-archives itemizes per archive (glob), tm-snapshots deletes per snapshot (`tmutil deletelocalsnapshots <date>`, date doubles as last-used) instead of blanket thinning.

- Safety hardening + execution (Prompt F): `regrow clean` executes plans — no ids cleans safe rules only, caution rules must be named; plan shown and confirmed first (`--yes` to skip). Trash mechanism complete: Finder move to the OS Trash (receipt records the real landed path, collision-renames included), staging-dir fallback when Finder is unavailable, rename-based so read-only trees (go mod cache) work; restore never overwrites a regenerated original. Every action is journaled to `~/.local/state/regrow/oplog.jsonl` *before* it runs; `regrow history` lists runs, `regrow undo [run-id]` restores trash moves (native commands recover via their regen story). Placeholder typos in `native_command` now fail at load; empty `{path}`/`{arg}` values skip the item instead of forming a wrong command. Rules can ship gated behind `--beta-rules`. Release pipeline: GoReleaser (darwin arm64/amd64), cosign-signed checksums, homebrew cask → `lbagic/homebrew-tap`. Verified end-to-end on a real machine: clean → Finder trash → undo → file back.

- Architecture deepening (pre-Prompt F): trash module now owns the trash mechanism — the Finder-move preview command moved from the planner into `internal/trash` (`PreviewCommand`), so the Phase 2 executor lands behind an existing seam; behavior and plan output unchanged. Golden harness rebuilt: every rule carries a `fixture:` block in its own YAML (files + fake tool-query items + optional host override), each rule scans an isolated fixture home and snapshots to `testdata/golden/<rule-id>.golden`, and coverage is enforced — a rule whose fixture stops matching (path rot) or lacks a fixture fails its subtest; stray goldens fail too. Rule PRs are now pure YAML: no Go edits, no shared-golden merge conflicts. Added `CONTEXT.md` (domain glossary) and `docs/plans/2026-07-13-architecture-review.md` (full review, candidates 3–5 parked). Small frictions from the same review: scan cancellation now reaches the filesystem walk (`DirSize`/`discover` honor ctx — a hung network mount can't wedge a scan), `Risk.Actionable()` replaces three inline surface-only checks, and the TUI scroll window has a short-terminal test.

- Rule catalog (Prompt E): 30 rules — every clean.sh module ported plus Tier-S targets. New: DeviceSupport, Archives, CoreSimulator caches/devices/runtimes (simctl-only), docker prune + volumes + VM-disk report, go mod, npm/yarn/pnpm, pip/uv, brew, node_modules discovery, TM snapshots, aerial wallpapers (Sequoia + Tahoe paths), mediaanalysisd cache, user logs, Spotlight reindex, stale macOS installers, /Library/Updates report, Empty Trash, ~/Library/Caches report, iOS backups report. Engine grew: argv-form `native_command`, `note` field for footgun warnings, glob paths, `Host.Root` for fixture-rooted system paths, tool queries (docker df, simctl devices/runtimes, tmutil) with unit-tested parsers. Golden plan covers all 30 rules; `DirSize` treats TCC-denied dirs as partial (du-style), not errors. First real-machine scan: 158.8 GiB found.

- TUI (Prompt D): Bubble Tea checklist — findings grouped by category, size-ranked, risk-colored (safe/caution/surface), regen story + cost for the row under the cursor, safe rules pre-selected, space to toggle, enter opens the plan screen (exact commands, trash destinations, skips with reasons) — nothing executes. `regrow scan` opens the TUI on a TTY; piped or `--json` keeps plain output.
- Rule engine (Prompt C): YAML schema {id, title, category, risk, version-aware per-OS paths, marker discovery, tool_query, native_command, regen, sudo}, strict loader with `--rules-dir` override, du-style size scanner + marker discovery + tool-query registry, dry-run planner emitting the exact command list with path guards and surface-only enforcement. CLI: `regrow scan|plan|rules|version`, `--json`. First 3 rules: xcode-derived-data, go-build-cache, rust-target-dirs. Golden-plan test harness.
- Scaffold: Go module, package layout, CI (macOS test + linux lint).
