# Architecture

Status: Phase 2 complete (execution, trash/undo, oplog, release pipeline); wedge features (Phase 3) next. This doc records structure and invariants; it grows with each phase. Product rationale lives in [PRODUCT.md](PRODUCT.md); build order in [PLAN.md](PLAN.md).

## Shape

Single static Go binary. Bubble Tea + Lip Gloss TUI. Rules are declarative YAML embedded at build time; code exists only for the weird cases (Docker df parsing, HF scan-cache, simctl).

```
cmd/regrow/        entrypoint, flag parsing, --json mode
internal/engine/   rule schema, loader, dry-run planner
internal/scanner/  size measurement, marker discovery, tool queries
internal/tui/      checklist UI, plan screen
internal/trash/    trash-not-rm + staging fallback, path guards, receipts
internal/oplog/    jsonl journal (grouping, undoable computation)
internal/executor/ runs plans across the trash/oplog seams; undo
rules/             *.yaml catalog (go:embed), --rules-dir override
```

## Data flow

scan → findings (semantic: what, why, regen story, cost, last-used) → user selection in TUI → **plan screen** (exact commands + trash destinations) → execute → oplog → undoable.

## Invariants (the fence)

1. Dry-run is the default; execution is opt-in per run.
2. Nothing is ever `rm`'d directly: trash first, staging dir fallback, `--rm` explicit opt-out.
3. Every destructive path passes the guard: never empty, `/`, `$HOME`, or mount roots.
4. Native steward commands over raw deletion (`go clean -cache`, `ollama rm`, `docker builder prune`, `simctl runtime delete`).
5. Risk classes are architectural, not cosmetic: `safe` (auto-clean), `caution` (review), `surface-only` (never deletable through us).
6. Every executed action lands in `~/.local/state/regrow/oplog.jsonl` before it runs.

## Testing

Fixture-$HOME builder + golden dry-run snapshots per rule. CI: macOS runner (Linux joins in v0.3). New rules ship behind `--beta-rules`.

A missing tool or stopped docker daemon means "rule does not apply", not a scan error. Parsers are pure functions unit-tested on canned output; the golden test injects fake queries.
- 2026-07-13 — risk calls during the port: `trash-empty` is caution (clean.sh said safe) because emptying the Trash destroys regrow's own undo buffer; `library-updates` is surface-only (root-owned, only cleanable by raw rm as root — outside the trash-first fence); `docker-volumes` stays caution-with-loud-note since volume data is not regenerable; ~/Library/Caches is surface-only pending per-app itemization.
- 2026-10-04 — no rewrite (Rust/JS): scans are bound by kernel metadata work — C `du` 9.6 s vs sequential Go 11.6 s on a 411k-entry tree, 35 s sys vs 6 s user for a full scan. The lever is parallel walking inside a tree (4 workers: 3.2 s); `getattrlistbulk` adds ~25% on top and can come later. Directory opens get a bounded probe because `open(2)` on another app's container can block forever without Full Disk Access. Evidence: [direction doc](plans/2026-10-04-direction.md).
- 2026-07-13 — `DirSize` never fails on walk errors, root included: TCC-protected dirs (~/.Trash, CoreSpotlight) Lstat fine but refuse ReadDir without Full Disk Access; the target exists and reports a partial (possibly 0) size, `du 2>/dev/null`-style.

Actions keep carrying the exact argv (plan/--json contract unchanged). Move/receipt/staging signatures are deliberately NOT stubbed — designed in Phase 2 when the executor (their caller) exists.
- 2026-07-13 — golden harness v2 (supersedes the shared-snapshot harness above): fixture data lives in each rule's YAML (`fixture:` — files in rule path syntax, fake tool-query items, optional host os/version override; default darwin/15.5). Each rule scans an isolated fixture home → `testdata/golden/<rule-id>.golden`. Hard coverage: embedded rules without a fixture, with scan errors, or matching zero items fail; stray goldens fail. `Fixture` is `json:"-"` and inert at runtime; Validate does not require it, so `--rules-dir` users aren't forced to write fixtures — the test enforces it for the embedded catalog only.
- 2026-07-13 — placeholder convention owned by the schema (Prompt F, review candidate 4): `Argv.Placeholders/PerItem/ExpandItem` live in `internal/engine/schema.go`; `Validate` rejects unknown `{token}`s at load and `{arg}` on rules without a tool query. Expansion refuses empty values (`simctl delete ""` must never form); the planner skips such items with a reason.
- 2026-07-13 — trash execution (Prompt F): the Finder osascript *returns the trashed item's POSIX path* (Finder renames on collision — "x 14.54.11"; the receipt must record where the item landed, verified against the real Finder). Preview and execution are the same argv by construction. Staging fallback (`~/.local/state/regrow/staging/<run-id>/`) is a plain rename — works on read-only trees (go mod cache) since only parents matter; cross-volume targets fail loudly and are out of scope for v0.1. `Restore` refuses to overwrite a regenerated original. TCC note: `~/.Trash` refuses *listing* without Full Disk Access but rename in/out of it by known path works — undo needs no FDA.
- 2026-07-13 — oplog protocol (Prompt F): two lines per action — `start` (synced *before* the action runs, invariant 6; journal failure refuses to act) then `done` (with trash receipt) or `fail`; `undo` lines reference the same (run, seq). `Run.Undoable` = done receipts minus successful undos, reverse execution order. Corrupt journal lines fail loudly — the journal is the undo contract, skipping lines could undo the wrong thing. One failed action never aborts a run: a half-finished run is exactly what undo makes safe.
- 2026-07-13 — `regrow clean` defaults (Prompt F): no ids = safe rules only (the TUI's pre-selection); caution rules must be named explicitly. Plan printed + confirmed (y/N on TTY, `--yes` when piped). `--rm` opt-out from PRODUCT.md deferred — no demand until someone asks. TUI plan screen stays terminal and points at `regrow clean`; in-TUI execution can land later behind the same planner/executor.
- 2026-07-13 — release (Prompt F): GoReleaser darwin arm64/amd64, homebrew *cask* (brews stanza deprecated upstream) into `lbagic/homebrew-tap` with a quarantine-strip hook, checksums signed keyless via cosign/GitHub-OIDC — "signed release" without the $99 Apple certificate, which waits for the GUI companion decision (Phase 5).
- 2026-07-13 — TUI (Prompt D): `regrow scan` opens the Bubble Tea checklist only when stdin *and* stdout are TTYs; piped/`--json` output is unchanged so scripting never breaks. Scan runs async behind a spinner. Safe findings start pre-selected; caution needs a tick; surface-only rows have no checkbox and space is a no-op — but the *planner* stays the enforcement point (the TUI passes selection through `engine.BuildPlan`, which skips surface-only regardless). Plan screen is terminal in Phase 1: enter shows exact commands, nothing executes. UI model is testable headless (scan fn injected, key msgs driven in tests). Shared display helpers (`HumanBytes`, `ShellJoin`) live in `internal/tui` and are reused by the plain CLI printer.
- 2026-07-13 — docker becomes a first-class Phase 3 provider (Prompt G2, research in docs/plans/2026-07-13-docker-usage-timestamps.md): volume last-used is *derived* (container Mounts × StartedAt/FinishedAt) and persisted in a scan-time usage ledger keyed `name+CreatedAt`, because Docker tracks last-used natively only for build cache and labels are immutable post-create. Volume deletion must export a tarball to staging first — VM-internal data can't reach Finder trash, and invariant "trash-not-rm" holds via the export. Classification tiers (protected/caution-named/caution-anon/safe) exist because dangling ≠ safe: live probe found all 3 dangling volumes were named, compose-labeled, active-project data.
- 2026-07-13 — item identity (Prompt G0, design in docs/plans/2026-07-13-item-identity.md): item key derives Arg → `~`-path → Label → positional (`engine/identity.go`, one place); full id is `ruleID/key`, split on the *first* `/` since rule ids never contain one. Selection stays `map[string]bool` — atoms are rule ids or item ids — so `BuildPlan`'s signature and chokepoint role are unchanged. Planner refuses a *partial* selection on a whole-rule native command (skip with reason) rather than over-delete; `Rule.PerItemActionable()` is the one derivation the planner and TUI share. `Plan.Unmatched` reports selectors that addressed nothing (`clean` errors, `plan` warns) — a typo'd UDID must not degrade to "nothing to clean". TUI holds item atoms only; the rule checkbox (all/`[~]`/none) is derived. Per-item `Risk`/`Note` fields deliberately wait for their first real producers (G2 classifier, G model metadata).
- 2026-07-13 — tm-snapshots refit (G0): `tmutil thinlocalsnapshots / N 4` → per-snapshot `tmutil deletelocalsnapshots {arg}` with the date parsed from the snapshot name (also supplies LastUsed). Rationale: thinning delegates *which* snapshots die to the OS — incompatible with per-item selection; delete-by-date is the precise steward command. Blanket thinning remains available by selecting the whole rule.
- 2026-07-13 — docker provider shipped (Prompt G2): `internal/docker` owns the daemon conversation (one memoized snapshot per scan behind an `Exec` seam; recorded-JSON tests), classification, the usage ledger and the volume export; `internal/scanner` keeps only thin query adapters. Tier→rule mapping: protected/keep-list/over-cap/recent volumes all collapse into one surface-only `docker-volumes-kept` rule with the reason in the item label — everything not offered for deletion is still visible, with why. Deviation from the prompt: `docker-prune.yaml` was retired rather than narrowed — `docker system prune -f` cannot honor per-item age filters, so displayed bytes would lie about what the command frees; three explicit safe rules (build-cache/containers/images) replace it. Age threshold fixed at 30d (not configurable — the build-cache rule's `unused-for=720h` is baked into YAML and must match the scanner's sum).
- 2026-07-13 — pre_action seam (Prompt G2): rules may name a registered executor hook (`pre_action: docker-volume-export`) that must succeed before each item's native command runs — no backup, no deletion. The name registry lives in the schema (typo fails at load, like placeholders); implementations are wired onto the executor by cmd. Export receipts are `Method: export`: journaled like trash receipts (even on a later command failure), excluded from `Undoable()`, and `Restore` refuses them pointing at the tarball — recovery is `docker volume create` + untar, by hand.
- 2026-07-13 — volume export cap defaults to 10 GiB (config `docker.volume_export_cap`): the tarball lands on the disk regrow is trying to free, so exports must be bounded. Over-cap volumes are not deletable through regrow at all (kept tier, "delete manually") — refusing beats deleting without a backup. Enforced twice: classifier (plan-time) and exporter (execution-time, plus a volume-still-exists probe mirroring the trash mover's Lstat).
- 2026-07-13 — first user config file (Prompt G2): `~/.config/regrow/config.yaml` (XDG), strict decode — an unknown key is an error, because a typo'd `keep:` silently meaning "keep nothing" is a data-loss path. Docker keep-list exists because docker labels are immutable post-create; config is the only durable "never touch this volume".
- 2026-07-13 — doctor (Prompt H, design in docs/plans/2026-07-13-doctor-phantom.md): hero bugs are rule metadata, not a scanner registry — `doctor: {flag_above, story}` on the rule that already owns the paths and fixture; `regrow doctor` scans exactly the rules carrying the block plus the phantom-space category, and report assembly is a pure engine function (`DoctorRules`/`BuildDoctorReport`), cmd only prints. Doctor is read-only by construction: it never builds a plan; fix lines point at `regrow clean <id>`. Threshold semantics: flagged strictly *above* `flag_above` — a healthy cache sitting at its round number must not scream.
- 2026-07-13 — phantom space is a category, not a flag (Prompt H): `category: phantom-space` groups tm-snapshots, docker-vm-disk and the new apfs-purgeable in both the main scan (PRODUCT.md §4 mock shows it top-level) and doctor. Category is already the product's only display grouping; a second `phantom: true` axis would create two grouping notions.
- 2026-07-13 — APFS purgeable via the JXA ObjC bridge (Prompt H): purgeable = `NSURLVolumeAvailableCapacityForImportantUsageKey` (Finder's purgeable-inclusive free) − `NSURLVolumeAvailableCapacityKey` (statfs free), read by `osascript -l JavaScript` in-process. Chosen over `tell app "Finder"` (TCC automation prompt), diskutil/system_profiler (container-free only — verified live they cannot see purgeable), and CGo Foundation (breaks CGO_ENABLED=0 release cross-builds).
- 2026-07-13 — docker-vm-disk switched from `paths:` to a tool query (Prompt H): the sparse file's story needs both numbers — allocated blocks (real) and apparent size (logical) — and a path rule can only report one. Still a plain file stat (no daemon; the phantom explainer must work with Docker stopped). `HumanBytes` moved `tui` → `engine` for the label; tui keeps a delegating alias.
- 2026-07-13 — docker rules graduated from beta (first real-machine burn-in: live probe classified the dakr volumes correctly, export→rm→undo verified). ML rules stay beta pending the same.
- 2026-07-13 — ML module (Prompt G, design in docs/plans/2026-07-13-ml-module.md): HF hub is enumerated *and* deleted without the `hf` CLI — the CLI is venv-bound (often absent beside a 100GB cache), and the cache has no DB and no cross-repo blob sharing, so trashing a whole repo dir is what `hf cache rm` does plus undo; invariant 4 reserves steward commands for stores a tool must GC. Ollama is the opposite call: scan reads the manifest store directly (server may be down) but deletion stays `ollama rm {arg}` — blobs are refcounted across models. Ollama `Item.Bytes` is *exclusive* bytes (what `ollama rm` frees); shared bytes annotate the label. Model rules are `caution` even where research/02 says Safe: regrow-safe means pre-selected, and auto-proposing "delete all your LLMs" (incl. non-repullable `ollama create` customs) is hostile. All 12 `ai` rules ship `beta: true`. `FixtureItem` grew `path` so path-trashed tool-query items golden-test.
- 2026-07-13 — TUI execute-on-confirm (lands the "in-TUI execution can land later" note from Prompt F): the TUI still never executes — confirming (plan → `x` → confirm screen → `y`, two gates on two screens, `enter` inert on the second) quits the alt-screen and returns `(plan, confirmed)` to cmd, which reprints the actions and runs the same `executePlan` as `regrow clean`. Execution stays outside the alt-screen because native commands need real terminal stdio (sudo prompts, docker streams) and the scrollback must keep a record of what ran.
- 2026-10-04 — Empty Trash runs first (PR 1, B5): rules carry `empties_trash: true` (validated: whole-rule native command, never `safe`) and the planner moves those actions to the front, so a run's own Trash moves land in an already-emptied Trash and `regrow undo` can still restore them. Before this, `trash-empty` ran in catalog order and permanently deleted what the same run had just trashed.
- 2026-10-04 — the planner reads the containment forest (PR 1; shape pinned in the [attack plan](plans/2026-10-04-attack-plan.md)): an item's parent is the nearest item from any rule whose path strictly contains it, and on equal paths the later rule is the child. A selected item with a planned ancestor is skipped ("inside X, also selected", where X is the nearest ancestor whose action stays in the plan); an actionable item holding a surface-only item is refused ("contains Y, which regrow never deletes"), and so is one at the same path as a surface-only item of an earlier rule, which the parent rule alone would miss. A whole-rule command cannot leave items out, so it still runs while any of its items is outside other actions, and its bytes count only those items. Action bytes are therefore disjoint and `Plan.TotalBytes` is the union. Only a planned ancestor subsumes: a refused or unselected one does not.
- 2026-10-04 — one default selection (PR 1, B8): `engine.DefaultSelection` (whole safe rules that found items and reported no error, as rule atoms) is what the TUI pre-ticks and what `regrow plan` and `regrow clean` use without ids. `BuildPlan` with a nil or empty selection plans nothing; supersedes "nil selects every finding" and `clean`'s private safe selection (2026-07-13 `regrow clean` defaults).
- 2026-10-04 — plan surfaces say when space comes back (PR 1): `Plan.Totals()` fills `FreesNow` (steward commands) and `AfterTrash` (Trash moves) of the pinned `engine.Totals`, which lands in `account.go` ahead of PR 2's `Account`. The TUI plan and confirm screens, `regrow plan` and `regrow clean` print both subtotals and an undo column per action ("undo restores" for Trash moves, "no undo" for steward commands); the blanket "Trash first, undo restores" copy is gone. After a run, the summary splits what executed by where it went: freed now, in the Trash (only Finder receipts, `Result.TrashBytes`), or in regrow staging when Finder was unavailable (`Result.StagedBytes`), which emptying the Trash never frees.
- 2026-10-04 — a failed Empty Trash stops the run's Trash moves (PR 1 review): `osascript … empty trash` can fail (an Apple-event timeout on a large Trash) while Finder keeps emptying, so a later move could land in a Trash that is being destroyed. `Action` carries `empties_trash`; when such an action fails, the executor skips every remaining Trash move with a reason in `Result.Skipped`, and steward commands still run. Skipped actions are not journaled because nothing ran.
- 2026-10-04 — `regrow help`, `-h` and `--help` print the subcommand list and flags to stdout (PR 1, B8). Flags parse with `ContinueOnError`: an unknown flag returns an error that points at `regrow help` and exits 1.
