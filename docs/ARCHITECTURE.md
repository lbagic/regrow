# Architecture

Status: Phase 2 complete (execution, trash/undo, oplog, release pipeline); wedge features (Phase 3) next. This doc records structure and invariants; it grows with each phase. Product rationale lives in [PRODUCT.md](PRODUCT.md); build order in [PLAN.md](PLAN.md).

## Shape

Single static Go binary. Bubble Tea + Lip Gloss TUI. Rules are declarative YAML embedded at build time; code exists only for the weird cases (Docker df parsing, the HF cache walk, simctl).

```
cmd/regrow/        entrypoint, flag parsing, --json mode
internal/engine/   rule schema, loader, dry-run planner
internal/scanner/  size measurement, marker discovery, tool queries
internal/tui/      checklist UI, plan screen
internal/trash/    trash-not-rm + staging fallback, path guards, receipts
internal/oplog/    jsonl journal (grouping, undoable computation)
internal/executor/ runs plans across the trash/oplog seams; undo
internal/headroom/ free/purgeable/swap samples, history, forecast, alerts
internal/autopilot/ tick and prune: single flight, deferral, autotrim gate
internal/jsonl/    fresh-line appends shared by the oplog and headroom history
internal/protocol/ `regrow engine`: JSON lines over stdio for a shell app (docs/ENGINE.md)
internal/selfupdate/ replaces ~/.local/bin/regrow with the latest GitHub release, once a day as it runs
rules/             *.yaml catalog (go:embed), --rules-dir override
app/               Regrow.app, the menubar shell around `regrow engine` (docs/APP.md): a SwiftPM
                   package (RegrowKit with no UI, Regrow the app), the scan page, its WebKit checker
scripts/           the app's signing identity, build and install, smoke checks
```

## Data flow

scan → findings (semantic: what, why, regen story, cost, last-used) → user selection in TUI → **plan screen** (exact commands + trash destinations) → execute → oplog → undoable.

tick → sample (statfs free, purgeable, swap) → `headroom.jsonl` → forecast + crossings → alerts; with autotrim and low headroom, `PrunePlan` → the same executor → oplog.

## Invariants (the fence)

1. Dry-run is the default; execution is opt-in per run. One exception: autotrim (`regrow tick --autotrim`, the engine's `tick{autotrim}`) runs a rule's `prune:` policy with no per-run opt-in, only while headroom is low, and only once the oplog holds a completed manual `regrow prune <name> --yes` of that rule.
2. Nothing is ever `rm`'d directly: trash first, staging dir fallback. Two exceptions: a `prune` action deletes Go build cache entries unused for the rule's `min_age` directly, with no Trash and no undo; and `aerial-wallpapers` deletes the aerial videos and the downloader's temp files as root, only while its `aerial-picks` hold is clear. Each is journaled with the files and bytes it deleted, as counted before and after: the cache's entries, and the videos in the aerial folder (the rule's `measure`), not the temp files, which only root can read.
3. Every destructive path passes the guard: never empty, `/`, `$HOME`, or mount roots.
4. Native steward commands over raw deletion (`go clean -cache`, `ollama rm`, `docker builder prune`, `simctl runtime delete`). One exception: the go-build prune is a raw `/usr/bin/find <GOCACHE> -ignore_readdir_race … -delete`, because Go has no "trim entries older than" command. It deletes only the kind of file Go's own trim deletes (an `-a` or `-d` entry inside a two-hex-digit shard dir), and refuses unless `go env GOCACHE` names the directory, its README carries Go's cache header, and it sits on the volume whose free space was measured. A second exception: the aerial videos are a raw `sudo /bin/sh -c '… find … -delete'` on two fixed folders, `.mov` files in idleassetsd's `Customer` and `CFNetworkDownload_*.tmp` files in its temp folders under `/private/var/folders/zz`, because macOS has no command that removes downloaded aerials.
5. Risk classes are architectural, not cosmetic: `safe` (auto-clean), `caution` (review), `surface-only` (never deletable through us).
6. Every executed action lands in `~/.local/state/regrow/oplog.jsonl` before it runs.

## Testing

Fixture-$HOME builder + golden dry-run snapshots per rule. CI: macOS runner (Linux joins in v0.3). New rules ship behind `--beta-rules`.

- 2026-10-04 — the planner reads the containment forest (PR 1; shape pinned in the [attack plan](plans/2026-10-04-attack-plan.md)): an item's parent is the nearest item from any rule whose path strictly contains it, and on equal paths the later rule is the child. A selected item with a planned ancestor is skipped ("inside X, also selected", where X is the nearest ancestor whose action stays in the plan); an actionable item holding a surface-only item is refused ("contains Y, which regrow never deletes"), and so is one at the same path as a surface-only item of an earlier rule, which the parent rule alone would miss. A whole-rule command cannot leave items out, so it still runs while any of its items is outside other actions, and its bytes count only those items. Action bytes are therefore disjoint and `Plan.TotalBytes` is the union. Only a planned ancestor subsumes: a refused or unselected one does not.

- 2026-10-04 — a failed Empty Trash stops the run's Trash moves (PR 1 review): `osascript … empty trash` can fail (an Apple-event timeout on a large Trash) while Finder keeps emptying, so a later move could land in a Trash that is being destroyed. `Action` carries `empties_trash`; when such an action fails, the executor skips every remaining Trash move with a reason in `Result.Skipped`, and steward commands still run. Skipped actions are not journaled because nothing ran.
- 2026-10-04 — `regrow help`, `-h` and `--help` print the subcommand list and flags to stdout (PR 1, B8). Flags parse with `ContinueOnError`: an unknown flag returns an error that points at `regrow help` and exits 1.
- 2026-10-04 — every filesystem call of a scan is bounded (PR 2, B1; supersedes the root-only open probe): `open(2)` on another app's container can block forever without Full Disk Access, and a blocked syscall ignores ctx. `internal/scanner/walk.go` owns the bound. Tree walks (`DirSize`, discover, the ollama manifest walk) and single-directory listings (glob parents, the hf hub) run 4 workers under a watchdog: a directory with no progress for the stall window is written off, its worker abandoned and replaced, the walk marked partial; single calls (root `Lstat`, discover roots, the Docker VM disk stat) run on a side goroutine with the same rule. Progress is marked every 32 entries, after the visit has stat'd or read them, so a huge healthy listing or a visit that touches every entry is not mistaken for a blocked one. A cancelled scan blocks the calls it leaves in flight the same way, so a rescan does not join them. Two concurrent walks that reach one stuck path before either writes it off each leave a goroutine on it; that is bounded by the rules whose trees overlap there. The opener is injectable; tests block it at depth 3 and on a glob parent and assert the scan returns and a child process exits. A written-off call keeps its goroutine, so its path (and everything below it) stays blocked and is not touched again until that call answers: at most one stuck goroutine per path, however many scans the process runs, and a folder that starts answering (access granted) is read by the next scan.
- 2026-10-04 — a call is written off only when nothing else answers either (PR 2, measured): on the owner's machine the gated mediaanalysisd folder was not blocked for good; its open answered in 1.0–1.8 s on an idle disk and in 9–13 s while a full scan loaded the same disk. A flat 3 s deadline (the prototype's) reported it unreadable where the unbounded scan had measured 87 MiB. So the rule has two halves: the call made no progress for the stall window (5 s), and the walker as a whole got no answer in that window. Waiting for a slow call costs nothing while other walks still run; a folder that never answers ends the scan at most one stall window after the last useful answer.
- 2026-10-04 — `Usage` and `Item.Partial` (PR 2, B3; supersedes "2026-07-13 — `DirSize` never fails on walk errors"): `DirSize` returns `Usage{Bytes, Newest, Partial}` and its only error is ctx's. A target that refuses or blocks, root included, is an item with `Partial` set, shown as "unreadable" (nothing measured) or "≥ X" (a lower bound) with "blocked or unreadable (Full Disk Access may be needed)" — a likely cause, not a diagnosis. `Finding.Err` is left for rule-level failures: a tool error, an unknown query, a cancelled scan. Where the scan could not even enumerate (a glob parent, a folder under a discover root, the hf hub, an ollama manifest folder), the finding carries a pathless Partial marker item; without a path no plan can act on it. The planner is unchanged: `DefaultSelection` still takes a safe rule whose item is unreadable, and the plan shows it at 0 B.
- 2026-10-04 — last-used is the newest mtime over files and directories (PR 2, B4): the item root's own mtime said "unused 225d" for a cache written yesterday, and file times alone fail the other way (npm stamps 1985 on package files, only the directories carry the install time). `hf-hub` items take the same `Usage.Newest`; the earlier walk for blob atime through the snapshot symlinks is gone, so an hf repo's last-used is now its last download or refresh, not its last read.
- 2026-10-04 — `engine.Account` counts every byte once (PR 2, B2): `Ledger.Exclusive` is an item's bytes minus its direct children's in the planner's containment forest, floored at 0 (a partial parent, or a tree that grew between two walks, can measure smaller than a child). Each item's exclusive bytes land in one bucket derived from its rule, in this order: phantom-space category → macOS-managed, surface-only → shown only, steward command → frees now, otherwise → after Trash. Scan text, the TUI footer and `--json` show the four buckets instead of one sum (279.8 GiB claimed against ~164 GiB distinct in the blind review); category headers lost their totals because a category mixes buckets. `regrow scan --json` is now an object `{findings, totals, exclusive}`; `Totals` and `Ledger` gained snake_case JSON tags for it. What the forest cannot see stays double-counted across buckets, not within one: pathless tool items (docker objects live inside `Docker.raw`; purgeable space is mostly the aerial videos), which is why macOS-managed is its own bucket.
- 2026-10-04 — PR 1 review notes settled with the ledger (PR 2). Docker volume removals stay in "frees now", the bucket their steward command implies, and that overstates them: the pre-action writes an uncompressed tarball of the same size into staging on the same disk, and blocks freed inside the VM return to macOS only as `Docker.raw` trims. Both volume rules are caution, per-item and never default-selected; a "frees once staging is emptied" figure belongs with the staging view of PR 5. Nesting stays lexical (`filepath.Clean`): discover roots are now walked through a symlink, and hits are deduplicated by real path (the root's real path plus the hit's path below it), so a symlinked or nested root cannot report a directory twice and an inner root keeps hits deeper than the outer root's depth limit; two rules that spell one path in different case, or reach it through different symlinks, are still not recognised as nested — the catalog spells shared prefixes the same way, and the catalog test of PR 6 (one owner per byte) is the place to enforce it.

- 2026-10-04 — the go-build prune is the one sanctioned exception to invariants 1, 2 and 4 (PR 4, policy in the [direction doc](plans/2026-10-04-direction.md) D3). Go deletes cache entries only after 5 days unused and has no command to trim sooner, while worktree-heavy build bursts fill the disk within those 5 days. So the `prune:` block (`min_age`, `keep_under`, `unless_running`; validated: `go-build-cache` only, risk safe, `min_age` ≥ 1h, `keep_under` > 0) is planned by `engine.PrunePlan` as an ordinary `Action{Kind: prune}` and run by the ordinary executor. The command is `/usr/bin/find <GOCACHE> -ignore_readdir_race -mindepth 2 -maxdepth 2 -type f -path '<GOCACHE, glob-escaped>/[0123456789abcdef][0123456789abcdef]/*-[ad]' ! -newermt '<last second of that hour> UTC' -delete`: an absolute find; only shard dirs, as Go's trim and `go clean -cache` walk them, because a GOCACHE set to a shared dir such as `~/.cache` holds other tools' files that also end in `-a` or `-d` (the hex class is spelled out, since fnmatch ranges can follow locale collation); a UTC date the BSD find parses; and a cutoff on a second boundary, because find's sub-second handling of `-newermt` differs between builds. find re-stats every file, so an entry used after planning survives. Go refreshes an entry's mtime at most once an hour when it uses it, so "entries used in the last 48 h are spared" holds to within about an hour. The target bytes are fixed before anything runs; free space is not re-read while deleting, since Time Machine snapshots can hold freed blocks. The cache comes only from `go env GOCACHE` (run with `GOTOOLCHAIN=local`, so it never downloads a toolchain), symlinks resolved, path-guarded, and the README must start with Go's cache header; the executor checks the header again just before running. The executor measures the cache before and after and journals what was deleted on the done or fail line (`oplog.Pruned`); the start line carries the estimate. Single flight is a flock on `prune.state` in the state dir, which also keeps the deferral clocks. A running `go`, `compile` or `link` defers autotrim; regrow's own process and its ancestors do not count, so the `go` of `go run ./cmd/regrow …` is not a build. After 2 h of deferral, broken by any gap over 1 h between ticks (a sleeping laptop is not a running build), and with free space under 10 GiB, it prunes anyway, and the `min_age` cutoff still spares entries in use. The 1 h gap needs ticks at least hourly (the menubar ticks every 15 min); with rarer ticks the override never fires. A manual prune refuses while a build runs. `regrow tick --autotrim` refuses until the oplog holds a completed prune of the rule (`autopilot.Gate`), so "on only after one manual run" is enforced by data; a prune that ran to completion opens it even if it found nothing left to delete. A locked gate fails the tick only when headroom is low enough that a prune would have run; otherwise the tick succeeds and says autotrim is locked. A manual `--yes` that ends in a skip (nothing 48 h old right after `go clean -cache`, or a cache under `keep_under`) journals nothing, so it says the gate stays shut. A prune whose find fails fails the command (exit 1) from both `regrow prune` and `regrow tick --autotrim`. `regrow history` counts a prune by its measured bytes, not the start line's estimate. Known limit: the cache is found by running `go` from PATH, and an app launched by LaunchServices has no `go` on PATH, so the prune is refused there; the menubar shell (PR 5) must pass the login shell's environment to the engine or keep the verified GOCACHE.

- 2026-10-04 — a line cut short no longer locks the oplog (PR 4 review; amends the 2026-07-13 oplog protocol). Autotrim journals when the disk is nearly full, which is when a write can stop halfway. `Append` holds a flock on the journal from its check of the last byte through the sync, and starts on a fresh line when the file does not end in a newline, so two regrow processes journaling at once (`clean` and `tick --autotrim`) cannot glue a line onto the other's fragment. `Read` skips blank lines and a line that is the start of one entry and nothing else: it opens with `{"time":` (Time is the first field and never omitted) or is a prefix of that, the parser runs out of input with no other error, and no second `{"time":` appears in it, since a fragment followed by a whole entry can parse to the end the same way. Skipping such a line can miss a restore but never undo the wrong thing: a start line that failed to write refused its action, a lost done line drops its receipt, and a lost undo line leaves a receipt whose restore fails because the item is back. Any other unparseable line, garbage, zeros or two lines glued together, still fails loudly. Known limit: a cut right after a `\`, inside a `\u` escape, or inside a number or `true`/`false`/`null` ends in a different parser error and is not recognised, so that journal still fails loudly until the line is removed by hand; this costs availability, never safety. `internal/jsonl` holds the fresh-line rule both journals share; when the file cannot be read it assumes a fragment, since a spare newline is a blank line and a missing one glues two lines.
